# libnfc: поддержка считывателей ODRFID

Форк добавляет считыватели ODRFID-M/N (USB `0483:A26A`, режимы CCID 1 и 2, см.
`odrfid-mne/l151_ll_rfid/Docs/ccid_setup.md`) в существующие драйверы libnfc.
Идентификация ACR122U не подделывается: прошивка сообщает собственную строку
`Open Development RFID Reader ...`.

## Изменения относительно upstream

| Файл | Изменение |
|------|-----------|
| `libnfc/drivers/acr122_pcsc.c` | имена PC/SC-считывателя `ODRFID` и `Open Development`; принимается префикс прошивки `Open Development RFID Reader `; буфер строки версии 128 байт с завершающим NUL (было 11); Direct Transmit ограничен 254 байтами (однобайтовый Lc) |
| `libnfc/drivers/acr122_usb.c` | в список поддерживаемых устройств добавлен `0483:A26A` (CCID должен быть интерфейсом 0) |
| `libnfc/drivers/pcsc.c` | `ODRFID` и `Open Development` добавлены в исключения универсального драйвера, чтобы считыватель не обслуживался им дважды |

## Какой драйвер выбрать

Оба драйвера обращаются к одному устройству и **не совместимы одновременно**:
`acr122_usb` при открытии делает USB reset всего устройства, из-за чего
`pcscd` теряет связь. Собирайте один из них.

| Сценарий | Сборка |
|----------|--------|
| Есть `pcscd` (Linux/macOS/Windows PC/SC) | только `acr122_pcsc` (Autotools: `--with-drivers=acr122_pcsc`; CMake: `-DLIBNFC_DRIVER_ACR122_PCSC=ON` и остальные драйверы выключены) |
| Linux без `pcscd`, прямой USB | только `acr122_usb` (`pcscd` остановлен) |

При сборке всех драйверов `nfc-list` (из `master`) открывает каждое найденное
устройство по очереди: после успешного `acr122_pcsc` открытие через
`acr122_usb` сбрасывает USB и следующие PC/SC-открытия завершаются ошибкой.

Для `acr122_pcsc` нужны настройки CCID-драйвера (Escape и VID:PID),
описанные в `ccid_setup.md`.

## Известное замечание

Неподдерживаемые опросы (FeliCa, NFC-DEP) прошивка честно отклоняет ответом
PN532 `D5 7F 10`. `acr122_usb` выводит при этом `Command Code verification
failed` в лог уровня error; результат (0 целей) верный.

## Наблюдение при совместной работе двух драйверов

Один раз при прогоне, где `acr122_usb` сбрасывал USB под работающим `pcscd`
(а `pcscd` затем был остановлен без PowerOff), плата осталась с открытым
слотом CCID: AT-команды отвечали «занято», перезапуск после `SET_USBMODE`
не наступал. Помог аппаратный сброс (`STM32_Programmer_CLI -rst`).
Повторить не удалось: обычный сценарий (только `pcscd`, затем остановка
`pcscd` без PowerOff и `SET_USBMODE` через Escape) работает. Не смешивайте
драйверы и не останавливайте `pcscd` во время обмена.

## Проверено (2026-09-29)

ODRFID3-N (JSMicro `82`), прошивка 3.13n, режим 1, Linux, libnfc `master`
(версия в заголовке 1.8.0), карта MIFARE Classic 1K:

| Драйвер | Результат |
|---------|-----------|
| `acr122_usb` (без pcscd) | `nfc-scan-device`, `nfc-list`, 20/20 опросов; `nfc-mfclassic r a u`: 64 из 64 блоков |
| `acr122_pcsc` (pcscd 2.5.1, libccid 1.8.2 с добавленным VID:PID) | имя считывателя и версия прошивки в строке устройства; 20/20 опросов; `nfc-mfclassic r a u`: 64 из 64 блоков |
| Сравнение | дампы двух драйверов побайтно совпадают |

Не проверялись: Type B, ISO-DEP, запись, Windows и macOS, версия из ТЗ (тег
`libnfc-1.8.0`; патч `odrfid-mne/tools/libnfc-1.8.0-odrfid.patch` для него
ложится, но проверялся на плате M).
